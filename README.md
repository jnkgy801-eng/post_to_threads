# 楽天 → Buffer → Threads 予約投稿(購入導線型)

楽天市場の商品を自動で選び、**Buffer経由でThreadsに予約投稿**する GitHub Actions 構成です。
投稿は「悩み → 解決の根拠 → 判断材料(評価・送料・単価・割安の根拠) → リプ欄にリンク」の型で、購入につながる導線を作ります。
Threadsの反応(閲覧数・返信)と、楽天アフィリエイトの売上レポートを使って、商品選定を少しずつ改善します。

## 全体の流れ

```
                    毎日 JST 05:00                         毎日 JST 06:00                       Bufferが指定時刻に投稿
 ┌───────────────────────────────┐   ┌───────────────────────────────────────┐   ┌──────────────────────────┐
 │ analyze-threads.yml           │   │ post.yml (schedule_to_buffer.py)      │   │ Buffer → Threads         │
 │ Threadsの閲覧数・返信を取得   │──▶│ 空き枠(48時間先まで)に商品を選び予約  │──▶│ 本文(画像つき)+リプ欄リンク │
 │ → feedback.json / report.md   │   │ → posted.json / post_log.jsonl を更新 │   └──────────────────────────┘
 └───────────────────────────────┘   └───────────────────────────────────────┘
                                                  ▲
        手動(任意): 楽天アフィリエイトのCSVを data/rakuten_reports/ に置く
        → import-rakuten-report.yml が data/sales_weights.json(ショップ別の売上重み)を更新
```

### `schedule_to_buffer.py` が1回の実行でやること
1. 設定を読み込む(必須の環境変数が無ければ、投稿せずに停止)。
2. 今から48時間先までの**投稿枠**を作る。Bufferに既にある予約と重なる枠は使わない(何度実行しても二重予約しない)。
3. 枠ごとに、
   - **質問のみ枠**: 商品なし・リンクなしの質問を作る(アカウント全体のリーチ用)。
   - **商品枠**: ジャンルのキーワードを重み付きでランダムに選び、楽天APIで検索 → 条件を満たす商品を1つ選ぶ → 本文とリプライを作る。
4. Bufferに予約(本文+画像+トピックタグ、リプ欄にリンク)。成功したら `posted.json`(重複防止)・`recent_templates.json`・`post_log.jsonl` を更新。
5. `DRY_RUN=true` のときはBufferに送らず、内容を表示するだけ。

### 投稿はどうなるか(商品枠の例)
**本文**(商品画像を最大3枚添付 / リンクなし / トピックタグ付き)

```
トイレットペーパーで、こんな悩みありませんか？
ストックがかさばって、置き場所に困る…

商品名に「倍巻」とあるトイレットペーパーが、ちょうど良さそうです。
★4.5(1,500件)・送料無料・1ロールあたり約50円・4,800円
💡同じ検索結果の10件の1ロールあたり中央値(約55円)より、約10%安い単価です

仕様・サイズは、下のリプ欄で確認できます👇
```

**リプ欄**(自分の投稿へのリプライ。リンクと【PR】はここ)

```
レビュー1,500件の商品です👇
【PR】トイレットペーパー シングル 96ロール 長持ち …
★4.5(1,500件) / 送料無料 / 4,800円
※単価は掲載価格÷数量の目安です。比較は予約時点の楽天検索結果が対象で、送料・クーポンは含みません
※価格・在庫は変動します
https://hb.afl.rakuten.co.jp/...
```

- 5と0のつく日・ワンダフルデーは、リプ欄の先頭に「要エントリー」付きの注記が入ります。
- セール期間は `SALE_EVENTS` に自分で入れたときだけ、セール注記が入ります。
- 質問のみ枠は「1,000円以内で生活の質が上がったものは？」のような質問1行だけです。

### 1日の投稿枠(JST・既定)
| | 質問のみ | 商品 |
|---|---|---|
| 平日 | 07:45 / 22:15 | 12:10 / 18:00 / 20:15 |
| 土日祝 | 09:30 / 22:15 | 15:30 / 18:00 / 20:15 |

各枠に最大8分のランダムなずれを足します。Bufferの無料プランは予約10件までなので、1日5投稿だと約2日分が上限です。

## 機能

### 商品選定
- **ジャンル**: 既定は `daily`(日用品: 食器用洗剤・洗濯洗剤・柔軟剤・ドリップコーヒー・トイレットペーパー・ティッシュ)と `seasonal`(月ごとの季節家電・日用品)。
  Threads利用者が日常的に買い足す日用品を主役にするため、日用品は出現2倍・季節は1倍(`DAILY_REPEAT` / `SEASONAL_REPEAT`)。
  `home` は反応が低かったため既定から外してあります(`NICHES` で再有効化可)。炭酸水・モバイルバッテリーは除外済み。
- **価格帯**: 2,000〜12,000円(`MIN_PRICE` / `MAX_PRICE`)。
- **除外**: ふるさと納税・中古・医薬品・予約販売・書籍ショップ・アフィリエイトURLが無い商品。
- **スコア**: `評価 × レビュー数の対数` × `1件の報酬見込み(価格 × 料率)` に、次の補正を掛けます。
  - 悩みに応える仕様ワードが商品名にある → ×1.15
  - 同じ検索結果の中央値より単価が安い(根拠を示せる) → ×1.10
  - ショップ別の売上重み(`sales_weights.json`) → ×0.5〜2.0
- **レビュー条件**: ★4.5/200件 → ★4.3/100件 → ★4.0/30件 の順に緩めて探します。

### 投稿文(AI不使用・無料)
- `scripts/pain_points.py` の「キーワード別の悩み辞書」と、商品名・キャッチコピーに**実在した仕様ワード**で組み立てます。
- 仕様ワードが無い商品は、具体的な悩みを結びつけず「選び方の悩み」+レビュー件数・価格の事実だけを書きます。
- 断定しません(「〜が候補になりそうです」「ちょうど良さそうです」)。「使ってみた」等の体験の偽装、除菌・消臭・改善・予防などの効能表現は入れません(テストで機械検査)。
- 判断材料の行: ★評価(100件以上のときだけ)・送料無料・単価・価格。
- 本文の締めは既定で100%「リプ欄へ誘導」(`ASK_CLOSING_RATIO=0`)。

### 単価と割安表示
- 対象: トイレットペーパー(1ロール)・ドリップコーヒー(1杯/袋/包)・洗濯洗剤/柔軟剤/食器用洗剤(1kg/1L換算)。
- 数量が商品名から一つに決まるときだけ計算します。「12ロール×8パック」「2個セット」「本体+詰め替え」のように曖昧な表記は計算しません。
- 「安い」と書く条件: 同じ検索結果の同単位の商品が**8件以上**あり、中央値より**10〜60%**安いこと。60%超は数量の誤読を疑って書きません。比較の根拠(何件の中央値か)を必ず併記します。

### 分析とフィードバック(自動)
`analyze-threads.yml` が毎日JST 05:00に、Threadsの閲覧数・返信などを取得し、投稿ログと本文・時刻で突き合わせます。

| ファイル | 内容 |
|---|---|
| `data/threads_metrics.json` | 投稿ごとの閲覧数・いいね・返信など |
| `data/feedback.json` | テンプレート/カテゴリ/キーワードの重み(0.5〜2.0。商品・質問のみ各15件に達するまでは出さず、完全ランダム) |
| `data/threads_report.md` | 人が読むレポート(上位/下位投稿、カテゴリ別、キーワード別、時間帯別、ショップ別) |

- 指標は閲覧数です。**閲覧数は売上と一致しない**ため、下の売上データの取り込みを併用してください。
- 時間帯は重みに使いません(`threads_report.md` を見て、枠は人が判断)。

### 商品の品質ガード(自動・無料)
- 販売可能(`availability=1`)でない商品は紹介しません。
- 成果が計測される楽天アフィリエイトURL(`hb.afl.rakuten.co.jp`)でない商品は紹介しません(報酬ゼロを防ぐ)。
- URLが350字を超える商品は紹介しません。リプ欄のURLが途中で切れると成果が計測されないためで、文字数超過時は説明文だけを削ってURLは必ず残します。
- 5と0のつく日・ワンダフルデーは、本文の締めの直前に「要エントリー」付きで入ります(購入の後押し)。

### 売上データの取り込み(半自動)
楽天アフィリエイトのレポートを自動取得する公式APIは確認できなかったため、CSVを置く方式です。
1. 楽天アフィリエイトの管理画面でショップ別レポートのCSVをダウンロード。
2. `data/rakuten_reports/` にアップロード(GitHubの画面からでOK)。
3. `import-rakuten-report.yml` が `data/sales_weights.json` を更新 → 以後の商品選定に反映。

重みは「紹介1回あたりの報酬」から計算し、紹介回数が少ない店は平均に寄せ、0.5〜2.0に制限します。報酬合計が0の間は何もしません。
列名は「ショップ」「確定報酬/発生報酬/報酬/売上」を自動判定し、判定できなければ列名を表示して止まります。手元実行: `python scripts/import_rakuten_report.py`

CSVにクリック数の列があれば、`data/sales_report.md` に **閲覧数(Threads) → クリック → 報酬** をショップ別に並べます。
どこで離脱しているか(クリック率が低い=本文・導線、クリックはあるのに報酬0=商品・価格・ページ側)を見分けられます。
また、`threads_report.md` の「訴求要素別」で、割安表示・単価・仕様ワード・5と0の日・締め・リンク位置ごとの閲覧数と返信率を比較できます。

## セットアップ
1. **楽天ウェブサービス / アフィリエイト**: Application ID・Access Key・アフィリエイトIDを取得。
2. **Buffer**: Threadsアカウントを接続し、`https://publish.buffer.com/settings/api` でAPIキーを発行。
3. **GitHub Secrets**

| Secret名 | 内容 | 必須 |
|---|---|---|
| `RAKUTEN_APP_ID` / `RAKUTEN_ACCESS_KEY` / `RAKUTEN_AFFILIATE_ID` | 楽天 | 必須 |
| `BUFFER_API_KEY` | Buffer | 必須 |
| `BUFFER_CHANNEL_ID` | Threadsチャンネルが複数あるときのみ | 任意 |
| `THREADS_ACCESS_TOKEN` / `THREADS_USER_ID` | 分析用(`threads_basic` + `threads_manage_insights`)。長期トークンは約60日で失効 | 分析を使うなら |
| `RAKUTEN_KEYWORDS` | **設定しない**(設定すると内蔵のジャンル設計が使われません) | 非推奨 |

4. **動作確認**: Actions → `Schedule Rakuten posts to Buffer (Threads)` → `Run workflow` → `dry_run=true` のまま実行し、ログの内容を確認。問題なければ `false`。
5. **トークン確認**(分析を使う場合): `Threads token check` を1回実行。

## 環境変数(`post.yml` の env で指定)
| 変数 | 既定 | 内容 |
|---|---|---|
| `POST_SLOTS_JST` / `ENGAGE_SLOTS_JST` | `12:10,18:00,20:15` / `07:45,22:15` | 平日の商品/質問のみ枠(`none` で無効) |
| `POST_SLOTS_WEEKEND_JST` / `ENGAGE_SLOTS_WEEKEND_JST` | `15:30,18:00,20:15` / `09:30,22:15` | 土日祝 |
| `HOLIDAYS_JST` | なし | 祝日(休日枠を使う日) 例: `2026-11-23` |
| `SALE_EVENTS` | なし | `2026-12-04..2026-12-11:楽天スーパーSALE` 形式 |
| `NICHES` | `daily,seasonal` | 他: `home storage clean beauty gadget food` |
| `POST_STYLE` | `problem` | `problem`(購入導線型) / `question`(質問型) / `mixed` |
| `ASK_CLOSING_RATIO` | `0` | 本文の締めを質問にする割合(0〜1) |
| `LINK_IN_MAIN_RATIO` | `0` | リンクを本文に置く実験の割合(0〜1)。本文に置く投稿は【PR】が先頭に付き、リプ欄は無し |
| `PR_IN_MAIN` | `false` | `true` で本文先頭にも【PR】(リプ欄は常に付く) |
| `MIN_PRICE` / `MAX_PRICE` | `2000` / `12000` | 価格帯 |
| `ATTACH_IMAGES` / `MAX_IMAGES` | `true` / `3` | 商品画像の添付 |
| `LOOKAHEAD_HOURS` / `MAX_SCHEDULED` | `48` / `10` | 予約を埋める範囲 / Buffer予約の上限 |
| `SLOT_JITTER_MINUTES` | `8` | 枠ごとのランダムなずれ |
| `USE_FEEDBACK` | `true` | `false` で分析結果・売上重みを使わない |
| `DRY_RUN` | 定期実行は `false` | `true` でBufferに送らない |

## ファイル構成
```
.github/workflows/
  post.yml                    予約(毎日 JST 06:00) ※必須
  analyze-threads.yml         Threads分析(毎日 JST 05:00) ※分析を使うなら
  import-rakuten-report.yml   売上CSV取り込み(CSV追加時) ※売上重みを使うなら
  threads-token-check.yml     トークン確認(手動)
scripts/
  schedule_to_buffer.py       本体(商品選定・投稿文・Buffer予約) ※必須
  pain_points.py              悩み辞書 ※必須
  analyze_threads.py          Threads分析
  import_rakuten_report.py    売上CSV → ショップ別の重み
data/                         実行で自動更新される(posted.json / sales_weights.json / sales_report.md など)
  rakuten_reports/            売上CSVを置く場所
tests/test_offer_copy.py      単体テスト
requirements.txt              requests
```

## 運用上の注意
- **返信への対応**: 返信が付いたら1時間以内に返すと配信が広がります(自動化していません)。
- **広告表示**: リプ欄(リンク側)には常に `【PR】` を付けます。本文には既定で付けません。ステマ規制上、本文を見ただけの人には広告と分かりにくくなるため、消費者庁のガイドラインや楽天・Threadsの規約を確認し、必要なら `PR_IN_MAIN=true` にしてください。
- **表現**: 効能の断定・体験の偽装・根拠のない「安い/お得」は入れない設計です。キーワードを追加するときは `pain_points.py` にも悩みと仕様ワードを追記してください(未登録だと汎用の悩みになり品質が落ちます。テストが漏れを検出します)。
- **同じ枠に二重予約しない**ため、何度実行しても安全です。`posted.json` で商品の重複も防ぎます。
- Threadsの長期トークンは約60日で失効します。分析が失敗したら再発行して `THREADS_ACCESS_TOKEN` を更新してください。

## 2026-11-18 改修: 「閲覧数が取れる質問」に収益導線をつなぐ

### 分析で分かったこと(直近125件)
| | 件数 | 閲覧数の中央値 | 備考 |
|---|---:|---:|---|
| 質問のみ(リンクなし) | 42 | 318 | 合計約98,000閲覧。上位は「1,000円以内で〜」(33,654 / 20,659) |
| 商品投稿(リンクあり) | 83 | 91 | 合計約13,600閲覧 |
| 直近の購入導線型(「リプ欄へ」で締める本文) | 3(+) | 6 | 1〜26閲覧まで低下 |

- 閲覧者のほぼ全員がフォロワー外(43,423 / 43,435)。**閲覧は質問投稿が稼ぎ、収益は閲覧の少ない商品投稿にしかない**構造だった。
- 「◯円以内で『買ってよかった』」型は閲覧数の幾何平均が約2,100で、他の質問(約270)の8倍。
- 商品投稿の「replies」には、リンクを置いた自分のリプ1件が含まれていた(83投稿で138件)。返信率は過大だったため、分析側で自分の返信を除外。

### 変更点
1. **質問のみ投稿に、商品リプを添える**(`ENGAGE_OFFER_RATIO`、既定0.6。残りは対照)。本文=質問(広告ではない)、リプ欄=【PR】つきの候補1つ(評価・送料・価格の事実のみ)。「◯円以内」の質問には、その価格以内の商品だけを置く。
2. **「◯円以内」型の質問を追加**(ID 18〜21)。
3. **商品投稿の本文を「会話の入口」に**: 質問で締め(`ASK_CLOSING_RATIO` 既定1.0)、評価・単価・価格・5と0の日はリプ欄へ。広告・仕様表に見える冒頭の型(ID 8/9/10/12)を廃止。
4. **枠の配分**: 商品3→2、質問のみ2→3(1日計5投稿のまま)。画像は既定でなし。
5. **セール対応**: `SALE_EVENTS` に楽天ブラックフライデー(11/19 20:00〜11/25 1:59)を設定。開始前は「◯から」、開催中は「開催中」と時刻で言い分け。セール期間は質問の半分を「買いまわり」等のセール向けにする。
6. **トピックタグの比較**: 商品投稿の半分を広い「暮らし」タグにし、レポートにタグ別の表を追加(`PRODUCT_LIFE_TOPIC_RATIO`)。
7. レポートに「商品リプあり/なし」の比較を追加。

### 見るべき指標
- `threads_report.md` の「商品リプの有無」: リプを添えても質問の閲覧数が落ちないか。
- 楽天アフィリエイト管理画面の**クリック数・注文数**(日別)。閲覧→クリックの率は、Threads側では取得できません。
